## Design notes / deviations
- `isStuck(s, thresholdMin, now=Date.now())`: accepts `lastActivity` as `number|Date|null` (SSE sends epoch ms; server rows are Dates). Boundary is strict `>` (matches v1). Optional 3rd `now` arg for deterministic tests — does not change the locked 2-arg call.
- `events-bus.ts`: module singleton pinned on `globalThis` via `Symbol.for` to survive Next HMR (same pattern as `src/db/index.ts`). Exposes `subscribe`/`publish`/`unsubscribe` (+ `subscriberCount` for tests). A throwing subscriber (closed stream) is isolated so it can't break the fan-out.
- `/api/events`: `auth()`-guarded (401 if no session), returns a `ReadableStream` with `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`. Emits initial `event: sessions\ndata: {type:'sessions',sessions:[...]}`, re-pushes on every bus event (refetches DB snapshot = ground-truth, not the event payload), `:keepalive` every 25s, cleans up (clearInterval + unsubscribe) on stream `cancel()`. Dates serialized to epoch ms.
- `useLiveSessions()`: `{sessions, connected, stuckIds}`; opens `EventSource('/api/events')`, parses `sessions` events, computes `stuckIds` via `isStuck` (threshold const 10 = v1 default; v2 has no `/api/config` yet), fires `Notification` once per NEWLY-stuck id (guarded by `Notification.permission==='granted'`), forgets recovered ids so they can re-alert. Closes ES on unmount.
