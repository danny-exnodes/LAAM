# V2 Wave 3 — Chat Parity Implementation Plan

> **Coordination plan.** Chat is stateful and interconnected, so TL owns the `ChatClient` orchestrator (all state + handlers) and a locked `components/chat/types.ts` (TL prep). 4 agents build DISJOINT slices: backend proxy endpoints, chat-stream+OCR backend, message-render UI, composer/settings/sidebar UI. UI components are PRESENTATIONAL — they take props + callbacks from ChatClient, hold no cross-component state.

**Goal:** Bring v2 `/chat` toward v1 parity: settings (model/temp/top-p/system), rich rendering (MarkdownView: tables/chart/map/code from Wave 0), attachments (file/URL/image + OCR), message actions (copy/edit/regenerate/delete + timestamps), composer power-ups (slash menu, token counter, drag-drop, shortcuts, scroll-to-bottom), sidebar UX (rename/search), export MD/JSON, plus the backend endpoints these need.

**Architecture:** Next route handlers port v1's endpoints (all auth-guarded; OCR shells `tesseract`, fetch-url SSRF-guarded — both pure Node, no new deps). `ChatClient` (TL) holds conversation/message/streaming/settings/attachment state and passes slices+callbacks to presentational components. Reuses Wave 0 `MarkdownView` (rich render — wiring it into /chat also finally exercises leaflet SSR) + `toMarkdown`/`downloadJson`/`downloadMarkdown` (export) + `useT`.

**Tech Stack:** existing only — no new npm deps. `node:child_process`/`fs`/`os` for OCR. recharts/leaflet/react-markdown already in via Wave 0.
